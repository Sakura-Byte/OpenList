# 隐藏路径与缺失路径一致：TDD

目标：按照现有规则被隐藏的路径，在 `/api/fs/list`、`/api/fs/get`、`/api/fs/dirs` 中表现得与不存在路径相同。

## 响应约定

现有规则判定为隐藏的路径，与真正不存在的路径均使用 HTTP 200 的现有 JSON 封装：`{"code":404,"message":"object not found","data":null}`。列表过滤仍不显示隐藏条目；有查看隐藏权限的用户按其他访问条件正常浏览。真正的密码错误仍为业务码 403，存储故障等真实服务器错误仍为 500。

这使前端走同一错误页面，不必更改密码页面。隐藏规则的匹配、继承、签名和分享授权不在此次变更范围。

## 测试方式

通过真实路由、认证中间件、临时 SQLite 和本地存储运行；通过元信息管理 API 配置隐藏、密码等条件。预期响应采用固定值，并与真实缺失路径的响应比较；不 mock 隐藏检查或数据库查询。

按一条失败测试、一项最小实现的顺序推进。正确行为的对照测试可以直接通过，但不替代红阶段证据。

| 06 | 父目录列表和 dirs 不显示隐藏条目；公开对象及总数保持正确 |
| 07 | 普通用户无查看隐藏权限时与游客相同 |
| 08 | 拥有查看隐藏权限的用户仍能读取、列出隐藏路径 |
| 09 | `.+` 配合向下应用命中的直接子项和下层条目均返回未找到 |

| 11 | 非隐藏的密码目录：错误密码保留 403，正确密码恢复访问 |
| 12 | 非隐藏的可读用户限制继续保留权限拒绝 |
| 13 | Hide 为空、无元信息、名称不匹配、未适用向下规则时正常浏览 |
| 14 | 元信息隐藏规则的增加/更新/清空：下一次请求正确隐藏或恢复 |
| 15 | 中文、空格及方括号文件名准确匹配；请求体和查询参数形式结果一致 |
| 16 | 不存在的挂载路径也使用相同未找到响应 |
| 17 | 非未找到错误保留 500：对文件请求 list/dirs 不会被伪装为未找到 |
| 18 | 前端通过隐藏路径和不存在路径进入相同错误视图；密码保护路径仍显示密码输入 |
